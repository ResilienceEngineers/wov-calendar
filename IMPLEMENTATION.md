# Window of Vulnerability (WoV) — Full Implementation Specification

This document is a complete, self-contained build spec for the **Window of Vulnerability** risk calendar. Paste it into a Claude Code session to implement the tool inside an existing site. Reference implementation: `github.com/ResilienceEngineers/wov-calendar` (you may copy files verbatim from there; this spec defines what each must do).

---

## 0. TL;DR — what you are building

A **12-month global risk calendar** that:
1. Plots recurring **patterns** (weather, cargo crime, cyber, conflict cycles, labour cycles) and **live events** (geopolitical, strikes, force-majeure) on one timeline.
2. Detects **convergences** — where multiple risks peak in the same window on the same region / industry / commodity / chokepoint — and scores them 0–10.
3. Applies a **Theory-of-Constraints** lens to maritime chokepoints (any single event on a chokepoint surfaces).
4. Tells companies, in plain language, **what to prepare for, when, and why**.
5. Lets users **add their own windows, choose which to see, and export/subscribe** to the calendar (iCalendar for Outlook / Google / Apple).
6. Refreshes daily and runs a **fortnightly pattern-research** pass that tracks whether patterns are materialising.

**Architecture in one line:** a static site (two HTML pages + JSON/CSV data) regenerated by a Python pipeline on GitHub Actions; Claude API is used only for signal triage and research, never for scoring or rendering.

---

## 1. Design principles (do not violate)

1. **Data is canonical; prose is decorative.** All calendar content lives in structured JSON/CSV. HTML is a thin renderer. The only prose blocks are the executive summary, methodology paragraph, and user-analysis narratives.
2. **`data/patterns.csv` is the single source of truth** for recurring patterns. Everything else about patterns is generated from it.
3. **Real patterns only.** A pattern qualifies only if it (a) recurs on a calendar cycle, (b) affects *multiple* industries / nodes / countries / regions, and (c) has a Tier 1–3 source and a measurable materialisation metric. Chronic-but-aseasonal phenomena are notes, not bands.
4. **Claude is the interpreter, not the engine.** Claude triages raw signals into typed records and researches patterns. It does **not** scrape, compute overlaps, score, or render. Deterministic Python does that.
5. **Claude output uses `###BEGIN:KEY### … ###END:KEY###` delimiter blocks, never JSON-wrapped responses** (JSON escaping fails at scale). JSON *content* may live *inside* a delimiter block.
6. **Stable IDs everywhere** so daily regeneration updates in place rather than duplicating (critical for ICS subscriptions).
7. **Scores must differentiate** — bounded additive components, no multiplier that saturates.

## 3. Data model

### 3.1 `data/patterns.csv` — single source of truth

One row per recurring pattern. CSV with `|`-delimited multi-value fields and `;`-delimited geo_bbox. Columns:

| Column | Type | Notes |
|---|---|---|
| `pattern_id` | kebab-case | stable; generated band id = `{pattern_id}-{year}` |
| `name` | text | human title |
| `category` | enum | `weather` \| `cargo_crime` \| `cyber` \| `conflict_cycle` \| `labor_cycle` |
| `subtype` | text | for weather = the hazard_type enum (see §3.4); else descriptive |
| `recurrence` | enum | `annual` \| `biannual` \| `cyclical` \| `episodic` |
| `start_month` `peak_start_month` `peak_end_month` `end_month` | int 1–12 | window in months; wraps year if end < start |
| `regions` | `\|`-list | region IDs (FK → vocab/regions) |
| `countries_iso3` | `\|`-list | ISO 3166-1 alpha-3 (descriptive, not FK) |
| `industries` | `\|`-list | industry IDs (FK → vocab/industries) |
| `commodities` | `\|`-list | commodity IDs (FK → vocab/commodities) |
| `chokepoints` | `\|`-list | chokepoint IDs (FK → vocab/chokepoints) |
| `baseline_severity` | int 1–5 | FK → vocab/severity |
| `confidence` | enum | `low` \| `medium` \| `high` (maps to signal tier in the engine) |
| `geo_bbox` | `s;w;n;e` | optional; else derived from union of region bboxes |
| `sources` | `\|`-list | source IDs (FK → sources.json) |
| `search_queries` | `\|`-list | queries the research run uses |
| `materialization_metric` | token | what to count to see the pattern "take off" (e.g. `named_storms_atlantic_ytd`) |
| `methodology_note` | text | why it is a real pattern |
| `first_identified` `last_reviewed` | YYYY-MM-DD | review tracking |
| `status` | enum | `active` \| `candidate` \| `retired` |

Seed ~35 patterns: 24 weather, 3 cargo_crime, 3 cyber, 2 conflict_cycle, 3 labor_cycle (examples in §9).

### 3.2 `data/observations.csv` — append-only materialisation log

Columns: `observation_date, run_id, pattern_id, category, search_query, source, metric_name, metric_value, unit, region, window_phase, materialization, source_tier, notes`.
`window_phase ∈ {pre, ramp, peak, decline, off}`; `materialization ∈ {emerging, on_track, accelerating, below_expectation, n/a}`. The fortnightly run appends rows; never rewrite history. This is how you watch a pattern climb against its baseline.

### 3.3 Vocabularies (`data/vocab/`)

- **regions.json** — `{ id, name, parent, countries_iso3[], geo_bbox:[s,w,n,e], why_it_matters }`. ~15 supply-chain-critical regions (Persian Gulf, Red Sea, Malacca, Taiwan Strait, NW Pacific, South Asia, EU Industrial, EU North, EU Med, US Gulf, Panama, Arctic, US West Coast, Sahel, Black Sea).
- **chokepoints.json** — `{ id, name, kind: maritime|port|inland_waterway, lat, lon, region_ids[], throughput_note }`. ~16 entries.
- **commodities.json** — `{ id, name, hs_code, category }`. ~47.
- **industries.json** — `{ id, name, naics_2 }`. ~39.
- **severity.json** — `levels: [{ level 1–5, label, color, trigger, examples[] }]`.

All band/event references to these are FK-checked by `validate_schemas.py`. Adding a pattern that needs a new region/industry means adding the vocab entry in the same change.

### 3.4 Generated band files

`build_patterns.py` reads `patterns.csv` and emits two files (do not hand-edit):

- **seasonal_bands.json** (weather rows): `{ version, generated_at, bands: [{ id, hazard_type, name, regions[], geo_bbox, start_date, peak_window:[s,e], end_date, baseline_severity, affected_industries[], affected_commodities[], affected_chokepoints[], source_ids[], confidence, notes }] }`. `hazard_type ∈ {tropical_cyclone, monsoon, flood, wildfire, drought, winter_storm, dust_storm, tornado_season, locust_outbreak, enso_modulator}`.
- **pattern_bands.json** (non-weather rows): `{ generated_at, source_of_truth, bands: [{ id, pattern_id, name, category, subtype, recurrence, regions[], countries_iso3[], industries[], commodities[], chokepoints[], geo_bbox, start_date, peak_window, end_date, baseline_severity, confidence, source_ids[], search_queries[], materialization_metric, methodology_note, first_identified, last_reviewed, status }] }`.

**Month→date resolution** (in build_patterns.py): pick the single occurrence whose window intersects `[today−30d, today+335d]`; handle year-wrap when `end_month < start_month`; derive peak dates from peak months; band `id = {pattern_id}-{occurrence_year}`.

### 3.5 Live data files

- **active_events.json** — `{ events: [{ id: "evt-YYYY-MM-DD-slug", event_type, title, start_date, end_date|null, est_end|null, regions[], countries_iso3[], industries[], commodities[], chokepoints[], severity 1–5, source_tier 1–6, signal_tier: hard|medium|soft|noise, source_ids[], upstream_tracker|null, supersedes|null, notes }] }`. `event_type ∈ {geopolitical_threat, strike_labor, strike_political, infrastructure_attack, port_closure, sanctions, cyber_incident, natural_realized, other}`.
- **fm_events.json** — `{ scraped_at, source_url, events: [{ id: "fm-<hash>", declarant, facility, country_iso3, declared_at, commodity_class, products[], wave 1–3|null, fm_type|null, status: red|amber|green|null, signal_tier, source_tier, regions_affected[], industries_downstream[], estimated_duration_days, source_doc_url|null }] }`. ID = `"fm-" + sha1(declared_at|declarant|facility|commodity_class)[:12]`.
- **hormuz_snapshot.json** — `{ scraped_at, source_url, snapshot: { brief_date, day_of_war|null, trend, trend_confidence, threat_level 1–5, threat_label, oneliner, watchlist[], map_pins:[{lat,lng,name,color,status}] } }`.
- **user_analyses.json** — `{ analyses: [{ id: "ua-YYYY-MM-DD-slug", uploaded_by, uploaded_at, trigger_commodity, trigger_geography, trigger_event_ref|null, industry_chain:[{stage,industry,lead_time_days}], timeline_projection:[{horizon_days,expected_impact,confidence}], regions_affected[], narrative_md }] }`.
- **sources.json** — `{ sources: [{ id, name, url, tier 1–6, domains[], reliability_score 0–1, last_calibrated?, notes? }] }`. Domains enum includes `seasonality, maritime, geopolitical, sanctions, energy_markets, shipping_data, labor, natcat, fm_declarations, upstream_tracker, political_violence, analytical, wire, regional_press, cyber, cargo_crime`.

## 4. The convergence engine (`compute_overlaps.py`) — exact spec

This is the core value. Implement precisely.

### 4.1 Load the band universe
Project every record into a typed `Band`: `{ id, start, end, regions, industries, commodities, chokepoints, severity, source_tier, signal_tier, kind, peak_start, peak_end }`.
- seasonal → `kind="seasonal"`, `source_tier=1`, `signal_tier="hard"`, peak from `peak_window`.
- pattern → `kind="pattern"`, `source_tier=2`, `signal_tier` from confidence (high→hard, medium→medium, low→soft), peak from `peak_window`.
- active → `kind="active"`, fields as given; no peak (peak=full window).
- fm → `kind="fm"`, `start=declared_at`, `end=declared_at+estimated_duration_days`, severity 3 default.
- user analysis → `kind="analysis"`, `start=uploaded_at`, `end=uploaded_at+max(horizon_days)`.
- **Exclude** any band whose subtype/hazard_type is `enso_modulator` (a year-long modulator that dilutes windows — it stays on the Gantt for context but never drives clusters).
- `is_live` = kind ∈ {active, fm, analysis}.

### 4.2 Cluster per axis
For each `axis ∈ {region, industry, commodity, chokepoint}`, for each `axis_value`:
1. Members = bands containing that value. Require ≥2 members.
2. Form **connected components** by sweeping full windows (sort by start; a band joins the current group if its start ≤ running max end).
3. For each component, compute the **peak-overlap window** via `densest_overlap` over each member's **peak** interval: sweep all interval boundaries, find the segment(s) with the maximum simultaneous count = `peak_depth`; the window spans those max-count segments; `active` = bands present in them. If `peak_depth < 2` (peaks don't coincide), fall back to `densest_overlap` over **full** windows.
4. If still `peak_depth < 2`, skip. Otherwise emit a cluster keyed by the peak window + `active` members.
5. **Cross-axis dedup:** sort all clusters by score desc; drop any whose member set overlaps an already-kept cluster by ≥80%.

### 4.3 Scoring (bounded, additive, 0–10)
```
depth_c        = min(3.0, 1.2 * log2(peak_depth))            # 0–3
severity_c     = 0.6 * mean(severity of `active` members)    # 0–3
concentration_c= 2.0 * (0.5*jaccard(industries) + 0.5*jaccard(commodities))   # 0–2
signal_c       = 0.5*frac(active are hard) + 0.5*frac(active are Tier-1)       # 0–1
chokepoint_c   = (axis==chokepoint ? (major?1.0:0.5)                           # 0–1, ADDITIVE
                  : (shared major chokepoint ? 0.5 : 0.0))
score = clamp(depth_c + severity_c + concentration_c + signal_c + chokepoint_c, 0, 10)
```
`jaccard` of a list of sets = |intersection| / |union| (0 if <2 sets or empty union). Major chokepoints = {hormuz, suez, bab_mandeb, panama_canal, malacca, taiwan_strait}. **SURFACE_THRESHOLD = 5.0.** Store `score_breakdown` for transparency on the UI. Never reintroduce a multiplier — it saturates.

### 4.4 Chokepoint constraint board (Theory of Constraints)
Independent of clusters. For each **maritime** chokepoint, collect all bands touching it:
- `red` if a live band touches it with severity ≥4 or a hard signal;
- `amber` if any live band touches it OR a baseline pattern of severity ≥3 is in window;
- `green` otherwise (or no bands).
Emit `{ state, exposure, what_to_watch, member_count }` with plain-language strings naming the highest-impact member. This is why a single event on a chokepoint surfaces even with no convergence.

### 4.5 Executive summary (the main message)
From the top-scoring cluster, produce an **action statement**:
`"Prepare {shared industries} for {axis_value} disruption — peak {window}. {depth} risks stack here (score X/10). Act {by date}."`
`prepare_by` = ~30 days before window start, or "now — window already open". Also emit `prepare_what / prepare_when / prepare_by / prepare_why` separately for the UI grid, and `chokepoint_phrase` (count + names of chokepoints under pressure).

### 4.6 Risk-by-month profile (when is the riskiest time)
12 forward months from current month. Each month's `intensity` = sum of `convergence_score` over **surfaced** clusters whose `time_window` intersects that month; `cluster_count` = how many. Mark `is_peak` on the max. The UI renders this as a bar strip with the peak highlighted.

### 4.7 narrative_seed
Deterministic one-liner per cluster: `"{Axis} {display}: {depth} risks peak together {window} (of {total} related), score X/10. Peak members: A + B + C. Shared industries: …; shared commodities: …."`

## 5. The pipeline (`update_brief.py` orchestrator)

Runs steps in order; each is a separate script; abort on non-zero exit; steps needing the Claude API are skipped if `ANTHROPIC_API_KEY` is absent (the rest still produces a calendar from patterns alone).

| # | Step | Script | Needs API | Purpose |
|---|---|---|---|---|
| 1 | build patterns | `build_patterns.py` | no | patterns.csv → band JSON |
| 2 | ingest Hormuz | `ingest_hormuz.py` | no | scrape Hormuz brief → snapshot + pins |
| 3 | ingest FM upstream | `ingest_fm_tracker.py` | no | scrape fm-tracker `BRIEF:FM_TABLE` |
| 4 | ingest FM web | `ingest_fm_websearch.py --if-thin` | yes | Claude+web_search FM supplement when upstream thin |
| 5 | triage signals | `triage_with_claude.py` | yes | classify new candidates → active_events |
| 6 | compute overlaps | `compute_overlaps.py` | no | the engine (§4) |
| 7 | render pages | `render_pages.py` | no | inject BRIEF:* blocks |
| 8 | build ICS | `build_ics.py` | no | regenerate .ics feeds |
| 9 | validate | `validate_schemas.py` | no | schema + FK gate (fail loud) |

### Scraper specs
- **ingest_fm_tracker.py** — fetch `raw.githubusercontent.com/<owner>/fm-tracker/main/index.html`; extract the `BRIEF:FM_TABLE` block; parse `<table class="fmtable">` rows positionally (Operator, Site/Chain, Wave, Type, Status, Date, Source); parse human dates ("12 May 2026", "~4 Apr 2026", ranges → first date); infer country/region/commodity/industries via an operator-keyword map; status red/amber by keyword; duration by keyword. Upsert by hash ID.
- **ingest_hormuz.py** — fetch the upstream brief's raw HTML; parse `BRIEF:DATE/DAY/TREND/THREAT/ONELINER/WATCHLIST` blocks and the `BRIEF:MAP_PINS` JS array (convert JS object literals to JSON: quote keys, single→double quotes, strip trailing commas).
- **triage_with_claude.py** — Sonnet, streaming, `web_search` (≤8–12 uses). System prompt encodes signal tiers + the controlled vocab + the chokepoint ToC rule. Returns `###BEGIN:JSON_EVENT###` blocks (one per net-new event), `###BEGIN:JSON_LEAD###`, `###BEGIN:VOCAB_GAP###`, or `###BEGIN:TRIAGE_STATUS###`. Script `json.loads` each block, schema-validates, dedups (exact ID; or same start_date + region ∩ + title-jaccard>0.7 → supersedes), appends.
- **ingest_fm_websearch.py** — same delimiter pattern, `###BEGIN:JSON_FM_EVENT###`; `--if-thin` only runs when upstream added <3 today.
- **research_patterns.py** (fortnightly) — reviews patterns whose `last_reviewed` ≥14 days; Claude+web_search returns `OBSERVATION` / `CANDIDATE_PATTERN` / `RESEARCH_STATUS` blocks; appends observations.csv, bumps last_reviewed, appends candidate rows (status=candidate) for human promotion.

### render_pages.py
Replaces content between `<!-- BRIEF:KEY_START -->` and `<!-- BRIEF:KEY_END -->`. Use a **lambda** in `re.sub` for the `<title>` update (digit-in-date backreference bug). After each page, assert the count of `_START` markers equals `_END` markers; fail loud on imbalance.

**BRIEF markers:**
- Shared (both pages): `TODAY_HUMAN`, `TODAY_ISO`, `LAST_UPDATED`, `DATA_VERSION`, `RISK_BY_MONTH`.
- index.html only: `HERO_KPIS`, `TODAY_GLANCE`, `CHOKEPOINT_BOARD`, `TOP_OVERLAPS`.
- brief.html only: `METHODOLOGY`.
Everything else on the pages is rendered client-side from `data/*.json` fetched at load.

### validate_schemas.py
Validate each `data/*.json` against its schema (jsonschema Draft 2020-12) **and** FK-check every region/industry/commodity/chokepoint/source reference against vocab. Non-zero exit on any failure — this is the CI gate.

Top-to-bottom: masthead (date/last-updated) → subnav (Deep view / Methodology / Sources / Pattern DB / Export PDF) → **Today at a glance** (`TODAY_GLANCE`: headline + prepare grid + chokepoint phrase + KPIs) → hero KPIs (`HERO_KPIS`) → **How to read this page** (`<details>`) → **Chokepoint constraint board** (`CHOKEPOINT_BOARD`) → **When is the riskiest time?** (`RISK_BY_MONTH` bar strip) → **Build & export your calendar** (`<details>`, §7) → **12-month risk calendar** (filter bar + SVG Gantt, client-side) → **Top convergence clusters** (`TOP_OVERLAPS` cards with score + breakdown + peak depth) → live-events ticker → FM pulse → custom-analyses strip → footer → 6-slide print-CSS PDF export.

### 6.3 Leaflet map (deep view)

- chokepoints → plain layer of white-filled markers with popups.
Use **click popups, not hover tooltips** (the original bug). `REGION_NAMES` lookup populated at init for popup text.

## 7. Personalisation + calendar export (client-side, localStorage)

**"Build & export your calendar" panel** (index.html, `<details>`):
1. **Add your own window** — form (title, family, start, end, note) → push to `localStorage["wov_custom"]`; render on the Gantt as a grey "MY WINDOWS" row and include in download.
2. **Choose which pre-analysed windows to include** — per-pattern checkboxes grouped by family with all/none; store the *deselected* set in `localStorage["wov_deselected"]` (so new patterns default to included). Keyed by `bandKey(id)` = id with trailing `-YYYY` stripped (survives yearly regeneration). Drives a "My selection only" Gantt filter.
3. **Export**:
   - **Download (.ics)** — build an iCalendar string client-side from selected patterns + custom windows; `Blob` download `my-wov-calendar.ics`. Includes private windows.
   - **Subscribe (auto-updating)** — link to the hosted `.ics` feeds; per-platform: `webcal://…` one-click (Apple/Outlook), copy-URL (Google "From URL"), and a Google add link.

**ICS event shape** (both client download and `build_ics.py`): all-day multi-day `VEVENT`, `DTSTART;VALUE=DATE` → `DTEND;VALUE=DATE` (exclusive, +1 day), `SUMMARY="[Family] Name (sev N/5)"`, `DESCRIPTION` with peak window + regions + industries + metric + note, `UID = {band-id}@{domain}` (**stable** so re-poll updates in place), `SEQUENCE` incremented daily, `CATEGORIES`, `TRANSP:TRANSPARENT`. Escape `\ ; , \n`; fold lines >75 octets (CRLF + space). Keep headers ASCII. `build_ics.py` emits `calendar.ics` (all) + one per family; add `REFRESH-INTERVAL;VALUE=DURATION:PT24H` and `X-PUBLISHED-TTL:PT24H`.

Hosted feeds carry **patterns only** (shared static file). Private custom windows can only travel via the client download (no per-user server on a static site).

## 12. Gotchas (hard-won — honor these)

1. Claude responses: **delimiter blocks, not JSON wrapping.** JSON content allowed *inside* a block.
2. `re.sub` for `<title>`/date replacement → use a **lambda** (digit-in-date is read as a backreference otherwise).
3. `max_tokens ≥ 24000` → must use `client.messages.stream(...)`.
4. GitHub Actions cron is best-effort → **multiple slots + skip-guard**.
5. **Stable UIDs** in ICS or subscriptions duplicate on every refresh.
6. Map: **click popups, not hover tooltips**; jitter co-located markers; cluster dense layers.
7. ICS: ASCII headers, escape special chars, fold long lines, all-day `DTEND` is exclusive (+1 day).
8. Scoring: **additive bounded components, never a multiplier** (it saturates to 10 and kills differentiation). Report the peak-overlap window, not the season union. Exclude year-long modulators (ENSO) from clustering.
9. Generated files (`seasonal_bands.json`, `pattern_bands.json`, `overlaps.json`, `*.ics`, HTML BRIEF blocks) — never hand-edit; on git conflict, re-run the pipeline.
10. Every vocab reference is FK-checked; add the vocab entry in the same change as the pattern that needs it.
